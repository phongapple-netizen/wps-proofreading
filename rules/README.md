# 内置校对规则包

本目录保存插件随包发布的内置规则包。规则包采用开放 JSON 格式，可在任务窗格“规则中心 → 内置规则包”中直接安装，也可以单独导出、修改和再次导入。

## 当前规则包

### 中文及公文基础规范

文件：`chinese-writing-basic.json`

用于中文正式文稿的低误报基础检查，包含中文标点、日期写法、常见用词和基础层次序号等。确定性较高的格式问题可以参与“一键修正”；存在上下文差异的规则只做提醒。

主要参考：
- GB/T 9704—2012《党政机关公文格式》
- GB/T 15834《标点符号用法》
- GB/T 15835《出版物上数字用法》

### 党政机关公文规则

文件：`party-government-document.json`

用于党政机关公文格式与行文核对，包含结构层次、发文字号、签发人、附件说明和部分文种/行文规则提醒。

主要参考：
- GB/T 9704—2012《党政机关公文格式》
- 《党政机关公文处理工作条例》

上下文依赖较强、但在当前段落范围内可以由模型辅助判断的规则，优先使用“AI核查”类型：关键词只负责触发，AI 结合上下文确认后才产生建议。仍然依赖全文位置或版式信息的规则（例如首次简称、标题样式）继续默认关闭，待后续增加全文和版式识别能力。

### 安全生产专业规则

文件：`work-safety.json`

用于安全生产监管、公文和检查材料，包含法定术语、“三个必须”、有限空间作业、高处作业、重大事故隐患标准时效等规则。

主要参考：
- 《中华人民共和国安全生产法》
- 《工贸企业重大事故隐患判定标准》（应急管理部令第10号）
- 国务院安委会有关安全生产职责分工文件
- AQ 3067—2026《化工和危险化学品生产经营企业重大生产安全事故隐患判定准则》

> 版本提示：本包版本日期为 2026-09-26。AQ 3067—2026 自 2026-09-30 起实施，因此对旧危化重大隐患判定文件仅提供“适用时点核对”提醒，不在 2026-09-26 提前自动替换。

## 设计原则

1. **低误报优先**：不能仅靠文本可靠判断的规则，默认关闭或只提醒。
2. **自动修正保守**：只有确定性强、替换结果唯一的规则才允许 `autoFix: true`。
3. **专业规则可追溯**：每条规则尽量填写 `source` 和 `notes`，说明依据与适用边界。
4. **上下文问题使用 AI核查**：需要语境判断的规则使用 `type: "ai_review"`，触发后只形成候选核查点，模型确认有问题才显示。
5. **AI核查不自动写入**：AI核查结果统一要求人工复核，不能进入“一键修正”。
6. **控制提示词体积**：每批只传递当前文字实际触发的 AI核查规则，并设置数量和长度上限。
7. **规则包可覆盖更新**：稳定 `id` 用于合并导入；同一 ID 的新版规则会更新旧规则，不重复创建。

## 新增规则包

新增内置包时：

1. 在本目录新增 JSON 文件；
2. 在 `catalog.json` 中登记；
3. 使用稳定、全局唯一的规则 ID；
4. 运行 `npm test`；
5. 对正则表达式、自动修正和专业依据进行人工复核。


## AI核查规则格式

AI核查规则示例：

```json
{
  "id": "example-context-review",
  "name": "专业术语上下文核查",
  "enabled": true,
  "group": "专业术语",
  "type": "ai_review",
  "pattern": "高空作业",
  "matchMode": "literal",
  "replacement": "高处作业",
  "instruction": "只有在安全生产专业语境中才建议使用“高处作业”；引用原文或专有名称时不要修改。",
  "severity": "medium",
  "autoFix": false,
  "priority": 90,
  "source": "专业规范",
  "notes": "关键词只用于触发核查。"
}
```

`matchMode` 支持 `literal`（固定文字）和 `regex`（正则触发）。`instruction` 是给模型的核查要求，必须填写；`replacement` 只是参考建议，可以留空。
